# SOS — Сервис онлайн-заимствования (демо)

Полнофункциональный демонстрационный проект сервиса онлайн-заимствования (СОЗ),
по модели, приближённой к регулированию РБ: заёмщик подаёт заявку, платформа
мгновенно строит скоринговую оценку (на основе мок-ответа АИС КР),
одобренная заявка публикуется в маркетплейсе, где её **целиком, одним
переводом, финансирует один инвестор** (без дробления между несколькими —
заявка строго 1:1). После полного финансирования заём выдаётся через мок ЕРИП,
строится график платежей, а при просрочке запускается процесс пени →
SMS-напоминаний → досудебной претензии → передачи на взыскание. Личность
обеих сторон сделки подтверждается через KYC-анкету и мок МСИ (Межбанковской
системы идентификации).

> ⚠️ **Важно.** Это демонстрационный/учебный проект, а не готовый к эксплуатации
> регулируемый финансовый сервис. АИС КР, ЕРИП, МСИ и SMS-шлюз — мок-интеграции
> (см. `backend/src/integrations`). Ставки, лимиты, пороги ПДН и сроки просрочки
> в `backend/src/config/legal-rules.config.ts` — иллюстративные настраиваемые
> константы, а не юридически выверенные значения. Перед реальным запуском СОЗ
> необходимы: юридическая проверка соответствия действующим НПА (включая Указ
> Президента №325 и акты Нацбанка РБ), регистрация оператора платформы в реестре
> Национального банка РБ и реальные интеграции с АИС КР/ЕРИП/МСИ.

## Структура репозитория

```
backend/    NestJS API (TypeORM + PostgreSQL, JWT-аутентификация, Swagger)
frontend/   Angular (standalone + Angular Material) — личные кабинеты
docker-compose.yml   Локальный PostgreSQL в Docker
package.json          Корневая оркестрация: одна команда поднимает всё целиком
```

## Быстрый старт (одна команда)

### Вариант A — совсем с нуля (Node.js/Docker ещё не установлены)

Скрипт `bootstrap` сам проверит, есть ли на машине Node.js и Docker, при
отсутствии попробует поставить их (через `winget` на Windows, `brew`/`apt`/
`dnf`/`get.docker.com` на macOS/Linux), а затем запустит проект.

```bash
git clone <адрес-репозитория> soz
cd soz
```

- **Windows** — дважды кликнуть `bootstrap.bat` (или в PowerShell: `.\bootstrap.ps1`).
- **macOS / Linux** — `./bootstrap.sh`.

> ⚠️ Docker Desktop (Windows/macOS) после установки требует один ручной
> первый запуск — принять лицензию и, на Windows, включить WSL2 (иногда с
> перезагрузкой). Это ограничение самого Docker Desktop, автоматизировать
> его нельзя. Если скрипт не дождался запуска Docker — сделайте это вручную
> один раз и запустите скрипт ещё раз, дальше всё пойдёт само.

### Вариант B — Node.js и Docker уже установлены

```bash
git clone <адрес-репозитория> soz
cd soz
npm install        # поставит зависимости корня + backend + frontend
npm run start:all  # поднимет Postgres в Docker, затем backend и frontend
```

`.env` не требуется — у всех переменных окружения есть рабочие значения по
умолчанию (см. `backend/src/config/configuration.ts`).

- Frontend: http://localhost:4200
- Backend API: http://localhost:3000 (Swagger: http://localhost:3000/api/docs)

Первый запуск на пустой базе автоматически создаёт схему БД (`synchronize:
true`) и демонстрационные данные — ничего дополнительно засеивать не нужно:

| Роль | Логин | Пароль | Что там есть |
|---|---|---|---|
| Админ | `admin` | `admin` | Учёт пользователей, очередь KYC, дела взыскания, лог SMS |
| 10 демо-инвесторов | `+375291300001` … `+375291300010` | `Demo12345` | Верифицированы (KYC+МСИ), баланс/вложено/заработано — с нуля |
| 10 демо-заёмщиков | `+375291200001` … `+375291200010` | `Demo12345` | У каждого одна опубликованная заявка в маркетплейсе, ещё никем не профинансированная |

На главной странице (`/`) сразу видны **маркетплейс с 10 заявками** и
обезличенные таблицы статистики по всем заёмщикам/инвесторам (ФИО маскируется
как «Г..........к П.С.»). Полный цикл сделки — инвестор открывает заявку →
«Инвестировать» → предложение и договор → заёмщик подтверждает в личном
кабинете (или отклоняет) → деньги поступают заёмщику → он видит график и
оплачивает — можно пройти целиком под любой парой демо-аккаунтов.

Остановить: `Ctrl+C` в терминале со `start:all`. Погасить контейнер Postgres:
`npm run docker:down` (данные БД сохраняются в volume между запусками; чтобы
начать с чистой базы — `docker compose down -v`).

Повторный `npm run start:all` на уже существующей базе демо-данные повторно
не создаёт (идемпотентная проверка по номеру телефона первого демо-инвестора).
Чтобы **пересеять демо-данные с нуля** в любой момент (удалить всех тестовых
заёмщиков/инвесторов и создать новых) — `POST /dev/cron/reset-demo-data`
(учётку `admin` не трогает; недоступно при `NODE_ENV=production`).

## Сквозной сценарий

1. Быстрая регистрация заёмщика (телефон → SMS-код → пароль, роль по умолчанию —
   заёмщик) → анкета KYC (мок-проверка паспортных данных) → обязательная
   идентификация через мок МСИ → подача заявки на заём.
2. Платформа синхронно запрашивает мок АИС КР (кредитный отчёт и долговая
   нагрузка), считает скоринговый балл/грейд/ставку и либо отклоняет
   заявку, либо публикует её в маркетплейсе с дедлайном сбора средств.
3. Регистрация инвестора (или переключение роли одной кнопкой из кабинета
   заёмщика — анкета и МСИ переиспользуются) → пополнение кошелька (мок) →
   инвестор открывает заявку в маркетплейсе (видит обезличенную статистику
   заёмщика: сколько сделок, сколько выплачено вовремя/не выплачено),
   нажимает «Инвестировать» — сумма резервируется, формируется договор займа
   (доступен для печати/сохранения обеим сторонам). Заявка ждёт решения
   заёмщика — он видит предложение и договор в личном кабинете и принимает
   или отклоняет. Если принял — платформа выдаёт заём (мок-выплата через
   ЕРИП) и строит график платежей (аннуитет), деньги сразу видны на балансе
   заёмщика; если отклонил или не ответил до истечения срока сбора — средства
   автоматически возвращаются инвестору.
4. Заёмщик оплачивает платежи через мок ЕРИП (с графиком-диаграммой и кнопкой
   печати); сумма распределяется по правилу «проценты → тело → пеня в
   последнюю очередь» и уходит инвестору на кошелёк — график заработка виден
   на графике в кабинете инвестора.
5. При просрочке — ежедневный (или ручной, через `/dev/cron/run-daily`) цикл
   начисляет пеню, отправляет SMS-напоминания (T+1/T+3/T+7), затем автоматически
   формирует досудебную претензию (T+30) и передаёт дело на взыскание (T+90).
6. Админ-панель (`admin` / `admin`): учёт пользователей (создание, блокировка,
   смена ролей, удаление), очередь KYC, дела взыскания, лог SMS, сводная
   статистика, применяемые юридические параметры.

## Тестовые скрипты

- `backend/src/modules/demo-seed/demo-seed.service.ts` — не скрипт, а сервис
  NestJS: автоматически засеивает демо-данные (см. «Быстрый старт») при старте
  backend на пустой базе. Ничего запускать вручную не нужно.
- `backend/scripts/overdue-test.mjs` — сценарий просрочки/взыскания через API + прямые правки БД.
- `backend/scripts/seed-admin.mjs` — альтернативный способ назначить роль
  ADMIN произвольному номеру телефона (не обязателен: встроенный `admin`/`admin`
  уже создаётся автоматически).
- `frontend/scripts/e2e-full-v2.mjs` — Playwright: главная → регистрация → KYC → МСИ → заявка → admin/admin → пользователи (скриншоты в `frontend/scripts/screenshots-v2/`).
- `frontend/scripts/e2e-charts2.mjs` — Playwright + API: полный цикл займа с графиком заработка инвестора и печатью графика платежей заёмщика.

Для запуска Playwright-сценариев нужен установленный браузер:
`cd frontend && npx playwright install chromium`.

## Известные упрощения (что стоит доработать перед реальным использованием)

- Юридические параметры (`legal-rules.config.ts`) заданы как статические
  константы, а не редактируемые из админ-панели настройки в БД.
- `synchronize: true` вместо версионируемых TypeORM-миграций.
- Нет реальных интеграций с АИС КР/ЕРИП/МСИ/SMS-провайдером — только
  мок-сервисы за интерфейсами (`*Port`) в `backend/src/integrations`, которые
  можно заменить на реальные реализации без изменения бизнес-логики.
- Нет отдельного аудит-лога административных действий.
